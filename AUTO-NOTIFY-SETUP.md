# Zero-Touch Order Alerts — the studio gets briefed like a bot message

From now on, **the customer never sends anything**. The second an order is created,
the server fires `notifyOwners()` which delivers the full hamper work-order
(items, extras, name, phone, address, occasion, gift note, totals) **plus the AI
hamper sketch** to you automatically — from a bot, never from the customer's number.

The order page now shows a green "🤖 Studio already notified — automatically" card,
and the customer's old send-button is gone (they keep an *optional* "add a personal
note" link, which is nice-to-have, not required).

## The channels (configure any; they run in parallel)

| # | Channel | What arrives | Cost | Setup | Approval? |
|---|---|---|---|---|---|
| **0** | **EMAIL (recommended)** | styled HTML order sheet + sketch attached & embedded | free | 3–5 min | no |
| 1 | Telegram bot | 🖼 sketch photo + full brief | free | 5 min | no |
| 2 | WhatsApp Cloud API (official bot) | template card, sketch image header + 10 fields | free | ~30 min | yes |
| 3 | Webhook | raw JSON for Make/Zapier/n8n/WATI | depends | 10 min | no |
| ~~4~~ | ~~CallMeBot~~ | **PAUSED BY PROVIDER** (site hides its number: "bot currently full") | free | — | — |

Do **Channel 0 now** — it needs no bot, no approval, no new phone: just an email address.

## Channel 0 — EMAIL alerts (do this first, 3–5 min)

Every order emails you a pastel order sheet: sketch on top, item table with extras,
customer + address block, totals, gift note, plus the raw text brief — and the sketch
is also **attached as a file** so you can forward it to suppliers.

**Option A — Resend (easiest, free 100 emails/day):**
1. `resend.com` → sign up with the email you want alerts on → verify
2. Left menu → **API Keys → Create API Key** → copy `re_…`
3. Netlify env vars: `RESEND_API_KEY=re_…` and `ORDER_NOTIFY_EMAIL=you@gmail.com`
   (Without a verified sending domain, Resend sends from `onboarding@resend.dev`
   to **your own account email** — exactly the owner-alert use case. Verify your
   domain later to send from `orders@tajgifts.in`.)

**Option B — your own Gmail, zero new accounts:**
1. Google account → **Security** → turn ON **2-Step Verification** (if not already)
2. Then **Security → App passwords** → name it `Taj Gifts Site` → create → copy the 16-char password
3. Netlify env vars:
   - `SMTP_USER` = your full gmail address
   - `SMTP_APP_PASSWORD` = the 16-char app password
   - `ORDER_NOTIFY_EMAIL` = where alerts go (same gmail or any other address)
4. Alerts then arrive from *your own address* — whitelist it in your phone's mail app.

**Test:** place a ₹699 COD test order → email lands in ~5–15 s → cancel the order in /admin.

## Powerful preview images (kills the "ugly sketch" problem)

The free image endpoint is a last-resort fallback now. With ONE free key the previews
are generated by a top-tier image model at order time, stored in your Supabase
Storage, and reused by the order page, the email and the work-order:

1. `aistudio.google.com` → **Get API key** → create → copy (free tier, no card)
2. Netlify env: `GEMINI_API_KEY=…`
   (Prefer OpenAI? `OPENAI_API_KEY=…` works too — Gemini is tried first.)
3. Supabase dashboard → **Storage → New bucket** → name exactly `previews` → **public bucket: ON**.
   (Service-role writes always work; public flag lets the order page & email show it.)
4. Next order: preview = crisp Gemini render, saved at
   `…/storage/v1/object/public/previews/<orderId>.jpg`.
   No key / key exhausted / bucket missing → automatic fallback to the improved
   free recipe. Nothing ever breaks.

## Channel 1 — Telegram bot (5 min, redundant second channel)

1. On your phone open Telegram → search **@BotFather** → `/start` → send `/newbot`
2. Name: `Taj Gifts Studio Alerts` · username: `tajgifts_studio_bot` (must end in `bot`; pick another if taken)
3. BotFather replies with the **token** — copy it: `123456789:AAF…` → this is `TELEGRAM_BOT_TOKEN`
4. Get your **chat id**: search **@userinfobot** → `/start` → it replies `Id: 123456789` → that number is `TELEGRAM_CHAT_ID`
   (Alternative: message YOUR new bot once with "hi", then open `https://api.telegram.org/bot<TOKEN>/getUpdates` and read `message.chat.id`.)
5. Netlify → Site → **Site configuration → Environment variables** → add:
   - `TELEGRAM_BOT_TOKEN` = the token
   - `TELEGRAM_CHAT_ID` = your id
6. Netlify redeploys automatically. **Test:** place a ₹699 COD test order on your site → within ~3 s your Telegram shows the sketch photo + the full brief. Cancel the test order in /admin afterwards.

## Channel 2 — official WhatsApp Cloud API bot, no second SIM needed (~30 min + review)

Meta gives every Business app a **free test sender number** that can message up to
5 verified recipients — perfect for owner alerts. (Later, for customer-facing
messaging, you'd attach a real SIM; not needed for alerts.)

1. `developers.facebook.com` → **Create app** → type **Business** → name `Taj Gifts Alerts` → create.
2. App dashboard → **Add products → WhatsApp** → Configure.
3. **WhatsApp → API setup**:
   - Left panel shows your **test number** + its **Phone number ID** → that ID is `META_WA_PHONE_ID`.
   - Right panel **"To"**: add recipient `+91 76688 19833` → Meta sends a one-time code to that WhatsApp → enter it → verified. (Up to 5 recipients.)
4. **Permanent token** (the panel token expires in 24 h — don't use it):
   Business Settings → **Users → System users → Add** → name `order-bot`, type **Admin** →
   select it → **Add assets** → tick your WhatsApp account (full control) →
   **Generate new token** → pick the system user → permissions `whatsapp_business_messaging` + `whatsapp_business_management` → **never expires** → copy → `META_WA_TOKEN`.
5. **Template with image header** — WhatsApp Manager → **Message templates → Create**:
   - Name `taj_order_alert`, category **UTILITY**, language EN
   - **Header: IMAGE** (puts the AI sketch on top of every alert)
   - Body, exactly 10 variables in this order:
     `🎀 New hamper order {{1}} — {{2}} ({{3}}). Total ₹{{4}} via {{5}}. Ship to {{6}} {{7}}. Deliver by {{8}}. Note: {{9}}. Status {{10}}.`
   - Submit → utility templates usually auto-approve within minutes.
6. Netlify env vars:
   `META_WA_TOKEN`, `META_WA_PHONE_ID`, `META_WA_TO=917668819833`, `META_WA_TEMPLATE=taj_order_alert`
7. Test order → the template card (sketch on top, all order fields below) lands on
   your WhatsApp **from the Meta bot number** — never from the customer.

## Channel 3 — webhook

`ORDER_NOTIFY_WEBHOOK=https://…` receives `POST {order, brief, artUrl}` JSON — plug into
Make.com / Zapier / n8n / WATI / AiSensy to fan out to email, Slack, Sheets, SMS, anything.

---

## Safety rails built in

- All channels are **fire-and-forget**: if Telegram/Meta/CallMeBot is down, checkout
  still succeeds; the order is always in Supabase + /admin anyway.
- Channels run **in parallel** — configure two for redundancy.
- Nothing secret ever reaches the customer's browser; tokens live only in Netlify env.
- Remove a channel any time by deleting its env var (deploy reloads them).

When alerts are flowing, the loop is closed: customer orders → bot briefs studio →
you tie & ship → status updates in /admin → customer tracks on the order page. 🎀
